# kcd2-inventory-preset-merger

Initial scanner/analyzer for Kingdom Come: Deliverance II `InventoryPreset__*.xml` mod patch files.

## Safety

Source mod files are read-only inputs. This milestone does not generate merged XML, rewrite source files, pack PAKs, or modify installed mods.

## Usage

```powershell
python -m kcd2_inventory_preset_merger check --mods-path fixtures/mods
```

By default, the CLI reads `config.json`:

```json
{
  "mods_path": "path/to/KCD2/Mods",
  "output_path": "./output",
  "generated_mod_name": "InventoryPresetMerge"
}
```

`--mods-path` overrides the configured Mods directory.

## Current Scope

The scanner recursively discovers `InventoryPreset__*.xml`, identifies the top-level mod folder for each file, parses `InventoryPreset` records, and reports presets touched by more than one mod.

The analyzer distinguishes additive overlaps from likely conflicts. It currently tracks:

- preset seen in only one mod
- preset modified by multiple mods
- identical duplicate children
- additive children from different mods
- same child `Name` with differing attributes
- differing attributes on the `InventoryPreset` itself

Supported child element types for this milestone:

- `PresetItem`
- `InventoryPresetRef`

## Runtime Validation

Before merge generation is implemented, runtime PTF merge behavior must be validated in-game. See [docs/runtime-ptf-merge-semantics.md](docs/runtime-ptf-merge-semantics.md).

## Conflict Check

The main user-facing command is:

```powershell
python -m kcd2_inventory_preset_merger check --mods-path path/to/Mods
```

It summarizes InventoryPreset interactions with these categories:

- `single_mod`
- `runtime_safe_additive_overlap`
- `same_logical_child_different_attributes`
- `identical_cross_mod_child`
- `preset_attribute_conflict`
- `unsupported_structure`
- `parse_error`

Use `--verbose` to show safe overlaps and full provenance.

## Merge Preview

The preview command writes a JSON report, but it does not install or modify any KCD2 mod files:

```powershell
python -m kcd2_inventory_preset_merger preview --mods-path path/to/Mods
```

Runtime testing confirmed distinct cross-mod `PresetItem` additions can coexist, so purely additive overlaps are classified as `runtime_safe_additive_overlap` and are not generated by default. Remaining merge focus is on genuinely ambiguous or conflicting cases such as explicit preset attribute conflicts, cross-mod identical child contributions, same logical child modified differently across mods, and unsupported child structures.

Confirmed runtime evidence: `inventorytest_a` added `bandage_classic` x100 and `inventorytest_b` added `recipe_fevertonicPotion` x100 to the same merchant `InventoryPreset`; both appeared simultaneously in-game with both mods enabled.

## Future Architecture

The InventoryPreset analyzer may later become a model for a generic KCD2 PTF conflict checker capable of identifying multiple mods that explicitly modify the same record or field in other tables. That generalization is not implemented yet.
