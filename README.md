# kcd2-inventory-preset-merger

Scanner, conflict checker, and conservative compatibility-mod generator for Kingdom Come: Deliverance II `InventoryPreset__*.xml` mod patch files.

## Safety

Source mod files are read-only inputs. The tool never rewrites source mods and does not implement PAK extraction, PAK packing, or automatic installation. Generated output, when available, is written as a separate loose compatibility mod under the configured output directory.

## Usage

```powershell
python -m kcd2_inventory_preset_merger check --mods-path fixtures/mods
```

By default, the CLI reads `config.json`:

```json
{
  "mods_path": "path/to/KCD2/Mods",
  "output_path": "./output",
  "generated_mod_name": "InventoryPresetMerge"
}
```

`--mods-path` overrides the configured Mods directory.

## Current Scope

The scanner recursively discovers `InventoryPreset__*.xml`, identifies the top-level mod folder for each file, parses `InventoryPreset` records, and reports presets touched by more than one mod.

The analyzer distinguishes runtime-safe additive overlaps from likely conflicts. It currently tracks:

- preset seen in only one mod
- preset modified by multiple mods
- identical duplicate children
- additive children from different mods
- same child `Name` with differing attributes
- differing attributes on the `InventoryPreset` itself

Supported child element types for this milestone:

- `PresetItem`
- `InventoryPresetRef`

## Conflict Check

The main user-facing command is:

```powershell
python -m kcd2_inventory_preset_merger check --mods-path path/to/Mods
```

It summarizes InventoryPreset interactions with these categories:

- `single_mod`
- `runtime_safe_additive_overlap`
- `same_logical_child_different_attributes`
- `identical_cross_mod_child`
- `preset_attribute_conflict`
- `unsupported_structure`
- `parse_error`

Use `--verbose` to show safe overlaps and full provenance.

When the scanner recovers a file that declares `encoding="us-ascii"` but contains UTF-8 bytes, `check` reports it as a non-blocking XML encoding warning. Source files are still never rewritten.

Confirmed runtime behavior: distinct additive child contributions to the same `InventoryPreset` coexist across enabled mods. In the runtime test, `inventorytest_a` added `bandage_classic` x100 and `inventorytest_b` added `recipe_fevertonicPotion` x100 to the same merchant `InventoryPreset`; both appeared simultaneously in-game. These cases are reported as `runtime_safe_additive_overlap`, not conflicts.

## Experimental Merge Preview

The preview command is experimental/internal for now. It writes a JSON report, but it does not install or modify any KCD2 mod files:

```powershell
python -m kcd2_inventory_preset_merger preview --mods-path path/to/Mods
```

Purely additive overlaps are not generated by default. Future merge work should focus on genuinely ambiguous or conflicting cases such as explicit preset attribute conflicts, cross-mod identical child contributions, same logical child modified differently across mods, and unsupported child structures.

## Generate

The production generation command is conservative and fail-closed:

```powershell
python -m kcd2_inventory_preset_merger generate --mods-path path/to/Mods --output-path ./output
```

It writes this separate loose mod layout only when the planner has mechanically safe generation candidates:

```text
InventoryPresetMerge/
  mod.manifest
  merge-report.json
  Data/
    inventorypresetmerge/
      Libs/
        Tables/
          item/
            InventoryPreset__merged.xml
```

Generation rules:

- `runtime_safe_additive_overlap`: never generated
- `preset_attribute_conflict`: unresolved, generation blocked
- `identical_cross_mod_child`: unresolved, generation blocked until duplicate semantics are known
- `unsupported_structure`: unresolved, generation blocked
- parse errors: generation blocked

If no mechanically safe generation candidates exist, no compatibility mod is written.

Generated output is validated before the command succeeds:

- `InventoryPreset__merged.xml` parses successfully
- `mod.manifest` exists
- manifest `modid` matches the generated `Data/<modid>/...` namespace
- `merge-report.json` exists and parses
- the generated mod directory contains only the expected generated files

PAK creation and installation are currently outside tool scope. Copying or packaging the generated loose mod should be done manually with your existing KCD2 mod workflow.

## Future Scope

This project remains scoped to `InventoryPreset` for the foreseeable future. A generic KCD2 PTF conflict checker for other tables is possible future scope only; it is not implemented or planned for the current milestone.
